# Проверка реализации

Дата: 2026-09-06.

- Полный набор из 25 тестов, включая API, успешно прошёл в [GitHub Actions](https://github.com/Hosttik/mine_video/actions/runs/34044284156); пропусков нет. Линтер также прошёл. Локально проверены ядро, контракты адаптеров и медиаконвейер.
- Реальный FFmpeg создал и ffprobe проверил MP4 H.264/AAC в 640×360 и 360×640, субтитры с кириллицей, JPEG и метаданные. Это тест кодировщика с явно синтетическим входом, не запись Minecraft.
- В текущей среде нет графического OBS, лицензированной сессии Minecraft, Docker и Java 21/Gradle. Сквозная игровая запись здесь не выполнялась.
- Fabric-мод успешно собран в GitHub Actions с Java 21 и Gradle 8.12: [сборка](https://github.com/Hosttik/mine_video/actions/runs/34044284156). Создан remapped JAR `minevideo-capture-0.1.0.jar`.
- Дополнительно добавлена и локально пройдена регрессия асинхронного старта OBS: получение ответа на StartRecord ещё не считается готовностью кодировщика. Текущий набор содержит 26 тестов; последующие результаты доступны в [CI](https://github.com/Hosttik/mine_video/actions/workflows/ci.yml).

Для приёмки на записывающей машине:

1. Выполнить установку из README и `mine-video doctor --launch`.
2. Снять `mob_arena`, `tnt_chain`, `tower_build`; проверить игровое окно, композицию, звук, субтитры и финальный кадр.
3. Сверить `capture.json` с реальным исходом боя. Проверить, что у таймаута нет выдуманного победителя.
4. Отменить активный job; запись должна остановиться, новый job должен выполниться.
5. Закрыть Minecraft во время записи; job должен завершиться ошибкой и остановить OBS.
6. Проверить длительную серию и расход диска на целевой машине перед работой без присмотра.

До этих проверок корректное обозначение — реализованный MVP с проверенным ядром и медиаконвейером, без подтверждённого live E2E.
